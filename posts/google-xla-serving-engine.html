谷歌开源 XLA Serving Engine：以 Apache 2.0 提供「用 Python 训练、用 C++ 推理」运行时；内部已服务超过每秒 600 万次查询

2026-11-05 · Google Open Source Blog

谷歌开源博客于 2026 年 11 月 5 日宣布推出 XLA Serving Engine（XSE）：面向 OpenXLA 生态的通用模型导出与推理运行时，以 Apache 2.0 许可开源。文章由 Google TPU Software 的 Oleg Shaldybin 与 Monica Song 执笔，目标是打通「Train in Python, Serve in C++」流程——多数工程师用 JAX、PyTorch 等 Python 框架训练，但部分生产环境因运维复杂度不允许运行 Python。用户可通过 API 把模型导出为包含 StableHLO 表示的「XLA SavedModel」，再由 XLA Serving Runtime 加载执行。

短请求场景下，XSE 吞吐量为团队所能构建的最佳 Python 服务器的 2–5 倍；内部已服务超过每秒 600 万次查询

官方称这一路径主要用于非大语言模型，以去掉 Python 解释器开销来换取更低延迟和更高吞吐。其研究显示：在短请求场景下，XSE 的吞吐量是团队所能构建的最佳 Python 服务器的 2–5 倍、是简易实现的 8–36 倍，每次预测的 CPU 时间减少 30%–70%，内存约为四分之一。文中写道，去年起已将核心组件投入谷歌内部生产；如今 XSE 服务超过每秒 600 万次查询，支撑 YouTube Shorts、Google Ads、Search 以及 Gemini Omni 的部分在线推理管道。运行时直接封装 PJRT 并由 XLA 编译器优化，支持单机与多机，保存 JAX 计算的 StableHLO 并用 Orbax 存权重，同时提供已在 CPU、GPU 与 TPU 上测试、暴露 gRPC 接口的 Docker 镜像。

预览合作方包括 Arm、Intel 与 Moloco。Moloco 员工机器学习工程师 Kunal Kukreja 称，其需求侧平台每天处理超过 6500 亿次推理、峰值达每秒 1050 万次查询。路线图提到计划与 TorchTPU 集成，让 PyTorch 用户也能导出 XLA SavedModel 并在 TPU 上用 C++ 服务；还将先对内、再对外提供提前编译（AOT）以缩短冷启动，并提供 C++ 数据预处理。官方同时提醒：XSE 是轻量的一次性推理引擎，对长上下文的自回归大语言模型，仍建议使用 vLLM 或 SGLang 等项目。代码与快速入门见 GitHub 仓库 openxla/xla-serving。
